## 11. 충돌 처리 정책 선택지 (합의 필요)

현재 방식은 **필드·챕터 단위 3-way 병합 + 같은 항목은 나중 전송 우선 + 병합 불가(목차 구조 동시 수정·삭제된 책)는 덮어쓰지 않고 "새 책으로 저장"** 입니다.

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 마지막 쓰기 우선(문서 단위) | 책 전체를 나중 기기 값으로 덮음 | 단순 | 다른 기기의 체크·메모가 조용히 사라짐 → 원칙 위반 |
| **B. 현행 유지(필드·챕터 단위 병합)** | 지금 방식 | 이미 구현·테스트됨, 서로 다른 항목은 모두 보존 | 같은 메모를 두 기기에서 동시에 고치면 나중 것이 남고 앞의 것은 사라짐 |
| C. B + 같은 메모 충돌 보존 | B에서 같은 챕터 메모가 양쪽에서 바뀌면 둘 다 남김(예: "다른 기기 메모" 표시와 함께 이어 붙임) | 메모가 조용히 사라지지 않음 | 병합 코드·문서 필드 추가(하위 호환 유지 가능) |
| D. 삭제 표시(tombstone) | 책 삭제 시 문서를 지우지 않고 `deletedAt`만 기록 | 오래된 기기에서의 부활을 서버가 확실히 막고, 실수 삭제 복구 가능 | 규칙·데이터 모델 변경(승인 필요), 목록에서 숨김 처리 필요 |

**추천: B를 유지하고 C를 추가.** 삭제 부활은 이미 막혀 있으므로(삭제된 책에 대한 변경은 덮어쓰지 않음) D는 "실수 삭제 복구"가 필요할 때 4단계에서 데이터 모델 변경 승인과 함께 검토하는 것을 권합니다.

함께 합의가 필요한 동기화 변경(합의 전에는 손대지 않음):
1. 일시 오류 자동 재시도(지수 백오프, 최대 간격 1분)
2. 손상된 대기 기록을 별도 키로 격리하고 나머지는 계속 동작
3. 대기 기록 크기 축소(기준을 챕터별 차이로 저장)
