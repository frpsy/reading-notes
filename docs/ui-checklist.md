# UI 결함 예방 체크리스트 (화면·디자인 변경 때 필수로 읽기)

> CLAUDE.md에서 옮김(2026-11-07, 내용 그대로).

## 책 화면 디자인 기준 (사용자 지정)

- 디자인 기준(사용자 지정): 사용자 입장에서 만든다. **책 상세에서 가장 중요한 것은 챕터 진도 체크**다. 체크 버튼·챕터 제목(눌러도 체크)이 가장 크고 누르기 쉬워야 하며, 메모·날짜·옵션은 보조 요소로 작게 둔다(목록의 메모는 2줄 미리보기, 처음 누르면 펼쳐 읽고 펼친 본문을 다시 누르면 편집창이 열린다. 기존 메모에는 연필 아이콘을 표시하지 않고, 메모가 없을 때만 작성 버튼을 둔다). 새 요소가 진도 목록을 밀어내거나 가리지 않게 한다. **챕터 체크·취소에는 팝업·알림창을 띄우지 않는다**(사용자 지정). 모바일 행 여백은 위아래 9px로 줄이고 체크 버튼 크기는 유지합니다. 줄의 어느 곳을 눌러도 체크되고, 취소는 다시 누르면 된다. 누를 때 깜박이지 않게 한다: 기본 탭 강조는 끄고(`-webkit-tap-highlight-color:transparent`), 호버 효과는 `@media (hover:hover)` 안에만 둔다. **정상 저장 완료 상태에서 상단 '저장됨' 버튼은 숨긴다.** 저장 상태 자체는 내부적으로 유지하고, 오프라인·저장 실패/재시도·진행 중 상태는 사용자가 알아야 할 때만 노출한다. 정상적인 빠른 저장에서는 헤더가 깜박이지 않아야 하며, 0.8초 넘게 걸릴 때만 '저장 중…'을 보여 준다. 이 원칙은 `e2e/smoke.mjs`의 상태 표시 회귀 테스트로 검증한다. 서버 응답은 순서가 뒤바뀌거나 늦을 수 있으므로, 방금 저장·삭제한 책은 10초 동안 더 오래된 응답으로 화면을 되돌리지 않는다(`state.recent`, `session.js` onSnap). 이 동작은 e2e의 `__realisticSnapshots`(오래된 응답 먼저 도착) 단계가 지킨다.

## 예방 규칙

원칙: **문제 발생 후 CSS 한 줄 수정하는 방식이 아니라, 변경 전에 위험을 점검하고 자동·수동 회귀 검증까지 완료한다.** 기기별 원인을 관찰 없이 단정하지 않는다.

1. **변경 전 영향 분석:** 화면 구조, 텍스트·글꼴, 색 대비, 배경·투명도, 스크롤, 헤더, 내비게이션, 입력 중 키보드, 안전 영역(Safe Area), 브라우저 캐시/서비스워커를 함께 확인한다. 특히 iPhone Safari, 홈 화면에 추가한 PWA(Progressive Web App), Android Chrome, PC를 구분한다.
2. **iPhone 상단 가독성:** Safari의 주소창·상태 표시줄·반투명/스크롤 경계 효과에 콘텐츠가 겹치지 않게 한다. `viewport-fit=cover`, `env(safe-area-inset-top)`, 실제 콘텐츠와 시스템 UI 사이 간격을 검토한다. 배경색은 `html`, `body`, `theme-color`까지 일관되게 관리한다. 화면을 아래로 당겼을 때만 글자가 선명해지는 현상은 **상단 시스템 UI 간섭의 단서**이므로 글꼴만 탓하지 않는다. CSS로 iOS 자체의 투명 효과를 제거했다고 주장하지 않는다.
3. **가독성과 조작:** 작은 글자에 과도한 음수 자간, 낮은 대비, 불필요한 opacity/filter/backdrop-filter/text-shadow를 사용하지 않는다. 버튼·링크는 44px 이상의 터치 영역을 확보하고, 포커스 표시·텍스트 200% 확대·다크 모드·긴 한국어 제목·320px 화면에서도 읽을 수 있어야 한다.
4. **반응형·레이아웃:** 320/375/390/430/768/1280px에서 가로 넘침, 제목·버튼 겹침, 잘림, 스크롤에 따른 변화, 줄바꿈, 하단 안전 영역, iPhone 동적 브라우저 툴바를 점검한다. 고정 헤더·sticky·blur는 근거가 없으면 추가하지 않는다.
5. **자동 검증:** `npm test`, `npm run e2e`, `e2e/design.mjs`의 Chromium·WebKit(가능하면 실제 iOS Safari 별도 확인), `npm run perf`, Firestore 규칙 테스트를 실행한다. 새 UI 결함은 **재현 또는 불변식 기반 테스트**(헤더 위치·겹침·글꼴·터치 크기·색 대비 등)를 추가한다. 테스트 통과가 실제 iPhone Safari 검증을 대신하지는 않는다.
6. **릴리스 확인:** CSS 변경 시 `index.html` CSS 쿼리 버전을 올리고, 서비스워커의 캐시/네트워크 동작과 GitHub Pages 배포 상태를 확인한다. PR에서 변경 전·후 모바일 스크린샷을 비교하고, 통과 후 병합한다. 배포·실기기 확인을 못 했으면 명시적으로 미확인이라고 보고한다.
8. **상단 상태 표시 최소화:** 정상 저장 완료는 화면에 버튼·배지를 남기지 않는다. 실패·오프라인·재시도 및 오래 걸리는 저장은 표시한다. 오류를 숨기거나 재시도 버튼을 없애지 않는다. 기능이 정상일 때 조용한 UI가 기본이다.
7. **회귀 방지:** 기존 독서 흐름과 계정·기록·동기화 구조를 건드리지 않고 필요한 범위만 고친다. 이전 수정이 다른 화면·브라우저·테마에 미치는 영향을 점검한다. 추가 기능이나 큰 리디자인보다 **눈에 보이는 문제의 예방, 신뢰성, 모바일 사용성**을 우선한다.

관련 검증: `e2e/design.mjs`의 `header safe-area and brand clarity` 및 `e2e/smoke.mjs`의 정상 저장 상태 숨김 검증. 다른 프로젝트의 UI 작업에서도 이 체크리스트를 활용하되 해당 프로젝트 구조에 맞게 적용한다.



## 다른 AI용 점검 요약 (이전 AGENTS.md)

- iPhone Safari의 상단 반투명 UI, 상태 표시줄, 스크롤 경계, `env(safe-area-inset-top)`, PWA 안전 영역과 배경 일치를 점검한다.
- 320/375/390/430/768/1280px, 라이트·다크, Chromium·WebKit에서 제목·버튼 겹침/가로 넘침·200% 글자 확대·44px 터치 영역을 검증한다.
- 변경 전·후 스크린샷과 자동 테스트를 확인한다. 새 결함에는 재현 또는 불변식 기반 회귀 테스트를 추가한다.
- CSS 변경 시 캐시 갱신 버전을 올린다. 실제 배포와 iPhone 실기기 확인 여부를 구분하여 보고한다.
- 저장·동기화·사용자 기록은 그대로 보존하고, 자동화 검증이 실패하면 운영 브랜치에 병합하지 않는다.
- **정상 저장 시 상단 '저장됨' 버튼은 숨긴다.** 실패·오프라인·재시도·장시간 저장만 안내하고, 정상 흐름에서 불필요한 상태 배지·알림을 새로 추가하지 않는다.
